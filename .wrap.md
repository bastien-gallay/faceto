# wrap configuration

Read by the `wrap` skill when a milestone closes. Written 2026-07-25 from what the first
unconfigured pass had to infer — if the repo moves, move these with it.

## Canonical locations

- index: `ROADMAP.md`                    # the feature catalog table; must match issues + Project #2
- lessons: `AGENTS.md`                   # standing guidance every agent loads
- skills: `.claude/skills/`              # operational lessons that are a procedure
- manual: `docs/src/`                    # the user-facing book (published to GitHub Pages)
- changelog: `CHANGELOG.md`              # what shipped, in Keep-a-Changelog form
- ci-reference: `docs/ci.md`             # canonical map of every CI job and workflow

There is **no ADR directory**. Cross-cutting decisions live as dated design notes at `docs/` root
(`event-sourcing-status.md`, `source-of-truth.md`, `multi-format-architecture.md`) and as prose in
the `ROADMAP.md` row that owns the feature. Do not invent `docs/adr/` during a wrap; if a decision
needs a home, add it to the row and say so.

There is **no dated journal**. `CHANGELOG.md` plus the per-row *Shipped <date> (PR #N)* note in
`ROADMAP.md` cover it.

## Verification commands

- blocking: `just ci`                    # fmt → clippy → test → js → markdown → book → deps → size → actionlint → justfile
- blocking: `just roadmap-check`         # every Now/Next row tracked; no orphan open issue
- advisory: none configured              # no link checker yet — in-page links are unverified

`just ci` needs four dev tools that are not Rust crates: `just`, `markdownlint-cli2`, `actionlint`,
`mdbook`. On macOS all four are `brew install`.

## Disposable zones

- `/docs/book/`                          # mdBook output
- `/docs/src/assets/sample.html`         # the tour's board, rendered at build time
- `/examples/*.svg`, `/examples/*.html`  # rendered boards
- `/serve.log`, `/mutants.out/`
- `.claude/worktrees/*`                  # per-milestone worktrees; remove once the branch merges
- `.DS_Store`

All of these are already gitignored. A wrap should *notice* them, not stage them.

## Never disposable

- `examples/*.model.json` and `examples/*.event-log.jsonl` — tracked fixtures; several tests and
  the published tour render from them.
- `.impeccable/critique/` — dated design-review snapshots. Generated, but not reproducible: they
  captured a UI state that no longer exists.
- `.personal/**` — untracked by design, and not the wrap's business.

## Commit conventions

- format: `<type>(<scope>): <the conclusion, lowercase>`
- types: `feat` `fix` `docs` `refactor` `test` `ci` `chore`
- scope: the module (`serve`, `render`, `events`, `client`) or the surface (`book`, `agents`,
  `roadmap`, `ci`)
- issue-pattern: `#\d+` — put `Refs #N` in the body, not the subject
- **Tidy First**: structural commits never mix with behavioural ones
- **No "Claude" signature, no "Generated with" footer**, in commits or PR bodies

## Project-specific wrap checks

- **A user-visible change must have reached `docs/src/`.** `AGENTS.md` § *Documentation is part of
  the feature* holds the change → page routing table. A milestone that shipped behaviour without
  touching the book is not closable; that is the point of the CI `docs book` job.
- **Three hand-maintained duplications drift silently.** Check them when the milestone touched
  their subject: the keyboard sheet (`src/template.html` `#help` ↔ `docs/src/board/keyboard.md`),
  the narrate skill's write-contract table (↔ `src/events/comments.rs`), and `docs/schema/*.json`
  (↔ the model/event fields).
- **`docs/ci.md` is canonical, and easy to forget.** Adding a CI job, a workflow or a third-party
  action means editing its jobs table, path-gating table, local-recipe table *and* pinning table.
- **Verify a mechanism before repeating a claim about it.** A doc comment can describe a design
  that was never built — `git log -S <identifier>` settles it in one command. See the phantom
  `/model-version` poll (PR #112).

## Notes

Learned the hard way, in wrap order.

- **`just ci` was unrunnable locally until 2026-07-26.** `just md` runs `markdownlint-cli2
  "**/*.md"`, and `.markdownlint-cli2.jsonc` had no `.personal/**` ignore — so the blocking gate
  failed on gitignored working notes that CI never lints. Fixed by adding the ignore. If a blocking
  check fails on a path CI cannot see, suspect the local/CI glob divergence before the content.
- **A count in a *shipped* row may be right.** `F-js-modules` says the client is 8 JS modules; it is
  9 today. The row was accurate at merge time and `connect.js` arrived later — so it gets a
  superseding pointer, not a correction. Before "fixing" a number in a ✅ row, check
  `git log --diff-filter=A` on the file that would change it. Present-tense inventories (`AGENTS.md`,
  live rows) are the ones that must be true *now*.
- **`ROADMAP.md` prose drifts where `sync_roadmap.py` cannot reach.** The script rewrites the
  `Status` / `Horizon` **columns of tracked rows** only. Narrative paragraphs that name issue numbers
  — the crowned-items list especially — go stale silently; two of three crowned items had shipped.
  Grep the prose for `#\d+` and check each state. Tracked as a wanted `--check` rule in #129.

  **And check the *counts*, not only the issue states.** Three of these have now been found — "8 JS
  modules" (9), "five upstream requests" (seven), "14 rows tracked as #114–#128" (15). A count is
  the drift that survives longest, because it reads as a fact rather than a claim and nobody re-runs
  the command. Two tells: a count sitting next to the range it counts (`#114–#128` is fifteen
  numbers), and a **sibling document holding a different number for the same thing** — that last one
  is only findable by grepping *across* files, which a pass focused on the files it just edited
  never does. When correcting one, say what is being counted; "14" was the feature count without
  the umbrella's own row, so a future reader would otherwise "fix" it back.
- ~~**Stale render outputs predate the naming convention.**~~ **Gone as of 2026-07-26** —
  the only render outputs left in `examples/` are `sample.svg` / `sample.html`, which `just ci`
  regenerates on every run. The disposable-zones list above is accurate again; nothing in
  `examples/` is dead. (The `*.model.json` / `*.event-log.jsonl` beside them are tracked
  fixtures — see *Never disposable*.)

- **Closing an issue freezes its roadmap row — set the Horizon on the board *first*.** Closing
  flips Project #2's `Status` to `Done`, and the next `just sync-roadmap` writes `✅` into the
  row. But `sync_roadmap.py` skips any row whose Status is already `✅` (*"Shipped is terminal"*),
  so **that run is the last one that will ever touch the row** — including its `Horizon` column.
  Close #114 without setting Horizon and the row sticks at `✅ | **Now**` forever, which no
  re-run repairs; only a hand edit does. Order: set both board fields, *then* sync, *then* close.
  (This is how `🔍 Reported` came to exist — see the Horizon legend in `ROADMAP.md`. It was added
  to Project #2's single-select **by hand, 2026-07-26**, and any future Horizon value must be too:
  `updateProjectV2Field` replaces the entire option list and can drop every other row's value.
  Never script it.)

  **And the close you must get ahead of is usually not one you type.** The note above reads as if
  someone runs `gh issue close` — so a wrap that never closes an issue by hand feels safe. It is
  not: a PR body containing `Closes #N` closes the issue **at merge**, which is the moment the
  freeze arms, and nobody involved ran a close command. That is exactly how #116 arrived at this
  wrap with `Status: Done` and `Horizon: Next` on Project #2. If the PR body says `Closes`, the
  board fields must be terminal **before the merge button**, not before a later cleanup.

  **Once it has fired, the file is the repair, not the board.** Editing the board afterwards
  achieves nothing — `sync_roadmap.py` skips a `✅` row, and it will skip it before it ever reads
  the board again. Hand-write both cells into `ROADMAP.md` (`| ✅ | ✅ Shipped |`), then confirm
  with `python3 scripts/sync_roadmap.py --check`, which should print *columns already in sync*.
  Set the board's Horizon too, so the two surfaces agree for a human reading the board — but know
  that it is cosmetic by then.

- **`main..HEAD` is a claim about a local ref, and the local ref is a cache.** PR #140's body was
  written from `git log main..HEAD` on a `main` that was five commits behind: it announced three
  commits and a four-file diff, and the PR contained one commit and one file. The other two had
  merged a week earlier as #139 — **from a branch of the same name**, which is what made the stale
  range look plausible. Two habits, both cheap: `git fetch --prune` *before* deriving anything from
  a range against `main`, and read the PR's own contents back after opening it
  (`gh pr view N --json commits,files`), because that is the only reading that comes from the host
  rather than from a local ref. Same family as the pruned-branch trap already in this file: reading
  a cache is not reading the thing.

- **`git add -A` is how an unreviewed file reaches `main`.** PR #142's fix commit swept in
  `examples/faceto-event-sourced-hotspot.event-log.jsonl` — an untracked extract artifact nobody
  had looked at — and it merged. `git diff --stat`, which is what you naturally run before
  committing, shows *tracked* changes only, so it gave no warning at all. Stage by name, and read
  the `??` lines of `git status --short` as decisions rather than noise. The cost here was a second
  PR (#143); in `examples/` specifically a committed `.jsonl` reads as a fixture and would have
  aged silently beside the board it was cut from.

- **A section you did not open is where the stale claim lives.** The F-extract milestone added an
  *Extract* section to `README.md` and left `## Status`, sixty lines below in the same file, saying
  "what is left of that loop is `extract`". Editing a file is not reading it: after adding a
  capability, grep the repo for the *absence* — "planned", "still missing", "what is left", "not
  yet" — not only for the feature's own name, which by construction appears in the places you just
  wrote. Same family as the counts trap above, one level up: the drift was a whole paragraph, and
  the file it sat in was already in the diff.

- **`just roadmap-check` reports success when it is blocked from checking.** Run inside the
  sandbox it prints `board unreachable … skipping` and `issues unreachable … skipping`, then
  `columns already in sync`, and **exits 0**. The real run needs network and fails loudly with
  `would update: …`. A gate that cannot reach its subject must be re-run outside the sandbox
  before its pass is believed — this is the general form of the linter-that-linted-nothing trap.
