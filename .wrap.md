# wrap configuration

Read by the `wrap` skill when a milestone closes. Written 2026-07-25 from what the first
unconfigured pass had to infer — if the repo moves, move these with it.

## Canonical locations

- index: `ROADMAP.md`                    # the feature catalog table; must match issues + Project #2
- lessons: `AGENTS.md`                   # standing guidance every agent loads
- skills: `.claude/skills/`              # operational lessons that are a procedure
- manual: `docs/src/`                    # the user-facing book (published to GitHub Pages)
- changelog: `CHANGELOG.md`              # what shipped, in Keep-a-Changelog form
- ci-reference: `docs/ci.md`             # canonical map of every CI job and workflow

There is **no ADR directory**. Cross-cutting decisions live as dated design notes at `docs/` root
(`event-sourcing-status.md`, `source-of-truth.md`, `multi-format-architecture.md`) and as prose in
the `ROADMAP.md` row that owns the feature. Do not invent `docs/adr/` during a wrap; if a decision
needs a home, add it to the row and say so.

There is **no dated journal**. `CHANGELOG.md` plus the per-row *Shipped <date> (PR #N)* note in
`ROADMAP.md` cover it.

## Verification commands

- blocking: `just ci`                    # fmt → clippy → test → js → markdown → book → deps → size → actionlint → justfile
- blocking: `just roadmap-check`         # every Now/Next row tracked; no orphan open issue
- advisory: none configured              # no link checker yet — in-page links are unverified

`just ci` needs four dev tools that are not Rust crates: `just`, `markdownlint-cli2`, `actionlint`,
`mdbook`. On macOS all four are `brew install`.

## Disposable zones

- `/docs/book/`                          # mdBook output
- `/docs/src/assets/sample.html`         # the tour's board, rendered at build time
- `/examples/*.svg`, `/examples/*.html`  # rendered boards
- `/serve.log`, `/mutants.out/`
- `.claude/worktrees/*`                  # per-milestone worktrees; remove once the branch merges
- `.DS_Store`

All of these are already gitignored. A wrap should *notice* them, not stage them.

## Never disposable

- `examples/*.model.json` and `examples/*.event-log.jsonl` — tracked fixtures; several tests and
  the published tour render from them.
- `.impeccable/critique/` — dated design-review snapshots. Generated, but not reproducible: they
  captured a UI state that no longer exists.
- `.personal/**` — untracked by design, and not the wrap's business.

## Commit conventions

- format: `<type>(<scope>): <the conclusion, lowercase>`
- types: `feat` `fix` `docs` `refactor` `test` `ci` `chore`
- scope: the module (`serve`, `render`, `events`, `client`) or the surface (`book`, `agents`,
  `roadmap`, `ci`)
- issue-pattern: `#\d+` — put `Refs #N` in the body, not the subject
- **Tidy First**: structural commits never mix with behavioural ones
- **No "Claude" signature, no "Generated with" footer**, in commits or PR bodies

## Project-specific wrap checks

- **A user-visible change must have reached `docs/src/`.** `AGENTS.md` § *Documentation is part of
  the feature* holds the change → page routing table. A milestone that shipped behaviour without
  touching the book is not closable; that is the point of the CI `docs book` job.
- **Three hand-maintained duplications drift silently.** Check them when the milestone touched
  their subject: the keyboard sheet (`src/template.html` `#help` ↔ `docs/src/board/keyboard.md`),
  the narrate skill's write-contract table (↔ `src/events/comments.rs`), and `docs/schema/*.json`
  (↔ the model/event fields).
- **`docs/ci.md` is canonical, and easy to forget.** Adding a CI job, a workflow or a third-party
  action means editing its jobs table, path-gating table, local-recipe table *and* pinning table.
- **Verify a mechanism before repeating a claim about it.** A doc comment can describe a design
  that was never built — `git log -S <identifier>` settles it in one command. See the phantom
  `/model-version` poll (PR #112).
